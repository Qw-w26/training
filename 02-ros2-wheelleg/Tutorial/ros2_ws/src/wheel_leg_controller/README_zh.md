# wheel_leg_controller（轮腿机器人控制器）

这是一个 ROS 2 控制节点，负责接收 `/imu` 和 `/joint_states` 话题的数据，计算 LQR 和 VMC 控制力矩，并通过 `/actuator_cmd` 话题发布 `rm_msgs/msg/WheelLegCmd` 类型的控制指令。

该节点不包含任何 MuJoCo 导入或仿真代码。仿真器仍然由独立的 `wheel_leg_sim` 节点负责运行。

## 控制算法（Control）

控制器使用以下参数：

- 控制周期：`dt = 0.002 s`。
- 车轮半径：`0.06 m`。
- 腿部标称长度：`0.10 m`。

12 元素的 LQR 增益通过 `lqr_update.py` 中的三次多项式系数计算得到。该文件复制自 `Wheel_Leg/LQR_VMC/lqr_update.py`。

这些系数源自 MATLAB 文件 `cal_lqr_k.m` 中的 LQR 拟合结果。

五连杆机构的正向运动学和雅可比矩阵力矩映射算法来自原始文件 `vmc_cal.py`。

每条腿均采用原始的腿长 PID 控制参数：

- 比例增益 P：`700`。
- 积分增益 I：`0`。
- 微分增益 D：`5`。

俯仰角和车轮状态反馈控制遵循 `robot_control_main.py` 中的实现。

机器人站立时的位置目标会随着机器人运动而更新；当请求速度为零时，位置目标将保持不变。

横滚控制器会围绕基础腿长，分别调整左腿和右腿的目标长度。

以下控制器类均实现在 `controller.py` 中：

- `BaseController`：基础控制器。
- `PIDController`：PID 控制器。
- `RollLegController`：横滚腿部控制器。
- `WheelLegController`：轮腿机器人控制器。

其中，三个具体控制器类均继承自公共基类 `BaseController`。

### 速度控制与反馈

`/cmd_vel.linear.x` 用于设置目标速度。

控制器使用以下速度变化限制：

- 加速率：`0.8 m/s²`。
- 减速率：`1.4 m/s²`。

速度变化斜坡根据成对状态消息之间实际经过的时间进行计算，因此每次调用时的速度变化量会随实际控制器更新间隔而调整。

原始 LQR 控制器中的车轮运动方向与 ROS 的 `linear.x` 定义相反。

因此，控制器会反转车轮方向的符号，并使用经过实测得到的参数：

`lqr_velocity_scale = 0.5`

该参数用于使控制器的指令速度与实际测量速度相匹配。

`/cmd_vel.angular.z` 用于设置偏航角 PID 控制器的目标值。

此外，控制器还提供可选的车轮速度 PI 控制功能。

默认情况下，该功能处于禁用状态，以便完整使用 LQR 平衡控制。可以通过参数 `wheel_speed_pi_limit` 启用这一附加控制功能。

## 手柄与键盘控制（Gamepad and Keyboard Control）

手柄和键盘两种输入方式都会通过 `/joy` 话题发布 `sensor_msgs/msg/Joy` 类型的消息。

**控制器本身不依赖键盘控制软件包 `keyboard_joy`。**

默认的 Xbox 手柄布局采用以下轴映射：

- `axes[1]`：控制前进和后退。
- `axes[3]`：控制偏航，即转向。

控制器使用通常的负轴符号约定。

可以通过以下参数修改轴索引和方向符号：

| 参数 | 作用 |
|---|---|
| `joy_linear_axis` | 指定控制线速度的输入轴索引 |
| `joy_yaw_axis` | 指定控制偏航的输入轴索引 |
| `joy_linear_sign` | 设置线速度输入的方向符号 |
| `joy_yaw_sign` | 设置偏航输入的方向符号 |

当有新的 `/joy` 消息到达时，控制器优先使用手柄或键盘输入。

如果超过 `joy_timeout` 指定的时间没有收到新的摇杆消息，控制器将恢复使用 `/cmd_vel` 话题进行控制。

默认超时时间为：

`joy_timeout = 0.5 s`

控制器会对输入应用以下限制：

- 输入死区：`0.1`。
- 速度限制。
- 加速度 ramp 限制。

还可以通过手柄按键调整目标腿长：

- 按下按钮 `5`：目标腿长增加 `5 mm`。
- 按下按钮 `4`：目标腿长减少 `5 mm`。

目标腿长的允许范围为：

`0.10–0.14 m`

### 1. 使用实体游戏手柄

如果使用实体游戏手柄，需要安装并运行标准 ROS 摇杆驱动程序。

这种方式不需要编译 `keyboard_joy` 软件包。

#### 第一步：安装 ROS 摇杆驱动

```bash
sudo apt install ros-${ROS_DISTRO}-joy
```

#### 第二步：枚举并检查手柄设备

```bash
ros2 run joy joy_enumerate_devices
```

该命令用于枚举系统检测到的游戏手柄设备。

#### 第三步：启动手柄驱动节点

```bash
ros2 run joy joy_node
```

启动后，驱动节点会将实体手柄的输入转换为 `/joy` 消息，供控制器使用。

### 2. 使用键盘控制

如果使用键盘输入，需要先在当前激活的 Python 环境中安装 `pynput`，然后编译可选的 `keyboard_joy` 软件包。

#### 第一步：进入 ROS 2 工作空间

```bash
cd Tutorial/ros2_ws
```

#### 第二步：编译键盘控制软件包

```bash
colcon build --packages-select keyboard_joy
source install/setup.bash
```

#### 第三步：启动键盘控制节点

```bash
ros2 run keyboard_joy joy_node
```

启动后，可以使用以下按键控制机器人：

- 方向键或 WASD：控制机器人运动。
- `5`：增加目标腿长。
- `4`：减小目标腿长。

键盘节点会从启动它的交互式终端直接读取按键。让该终端保持焦点并在其中按按键。可在另一个终端运行 `ros2 topic echo /joy` 查看轴值变化。

**注意：同一时间只能运行一个 `/joy` 输入源。**

也就是说，如果使用实体游戏手柄，就不要同时启动键盘控制节点，否则两个输入源可能相互干扰。

## 运行方法（Run）

首先，确保 ROS 2 环境和 Python 环境已经正确激活。

进入工作空间 `Tutorial/ros2_ws`，执行以下命令编译控制器及其依赖项：

```bash
colcon build --symlink-install --packages-up-to wheel_leg_controller
source install/setup.bash
```

### 第一个终端：启动 MuJoCo 仿真器

执行：

```bash
ros2 run wheel_leg_sim wheel_leg_sim --ros-args -p viewer:=false
```

其中：

- `wheel_leg_sim`：负责运行 MuJoCo 仿真的 ROS 2 节点。
- `viewer:=false`：关闭 MuJoCo 图形查看器。

### 第二个终端：启动轮腿机器人控制器

在另一个已经加载相同工作空间环境的终端中执行：

```bash
ros2 run wheel_leg_controller wheel_leg_controller
```

### 第三个终端：启动一个输入节点

根据实际使用的输入设备，选择以下两种方式之一。

**方式 A：使用实体游戏手柄**

```bash
ros2 run joy joy_node
```

**方式 B：使用键盘**

首先确保已经编译可选的 `keyboard_joy` 软件包，然后执行：

```bash
ros2 run keyboard_joy joy_node
```

### 使用 `/cmd_vel` 控制机器人

如果不使用键盘或手柄，也可以通过 `/cmd_vel` 话题控制机器人。

发布的消息类型为：

`geometry_msgs/msg/Twist`

当控制器没有收到新鲜的 `/joy` 输入时，就会使用 `/cmd_vel` 作为控制输入。

## 平衡控制测试结果（Balance Result）

测试环境：

- ROS 2 版本：Jazzy。
- MuJoCo 版本：3.17.0。
- 仿真查看器：关闭，即 `viewer:=false`。
- 实时仿真：启用，即 `realtime:=true`。
- 仿真速度：1 倍实时速度，即 1x。

在同一次测试中，机器人依次完成了以下阶段：

1. 原地保持平衡 5 秒。
2. 以 `0.3 m/s` 的指令速度运动 12 秒。
3. 停止运动，并在接下来的 5 秒内逐渐稳定。

整个测试过程中，机器人的俯仰角始终小于 10°。

### 各阶段测试结果

| 阶段 | 测试内容 | 测试结果 |
|---|---|---|
| 阶段 1：ROS 通信链路 | 检查 `/joint_states` 到 `/actuator_cmd` 的数据链路，并确认仿真以 1 倍实时速度运行 | 通过 |
| 阶段 2：车轮 PI 控制 | 设置 `wheel_pi_only:=true`、`wheel_speed_kp:=6`、`wheel_speed_ki:=0`、`wheel_speed_pi_limit:=1`，目标速度为 `0.5 m/s` | 平均速度为 `0.413 m/s`，误差为 `17.4%`；通过，误差小于 20% |
| 阶段 3：VMC 控制 | 计算最后 5 秒内两条腿腿长的平均值，目标腿长为 `0.10 m` | 平均腿长为 `0.09849–0.09869 m`，最大误差为 `1.51 mm`；通过，误差在 ±5 mm 范围内 |
| 阶段 4：平衡控制 | 测量开始阶段 5 秒内的静止平衡状态 | 俯仰角绝对值最大为 `0.116°`；通过 |
| 阶段 5：速度控制与恢复 | 以 `0.3 m/s` 运动 12 秒，然后停止 | 里程计记录的运动距离为 `3.686 m`，平均速度为 `0.307 m/s`，俯仰角绝对值峰值为 `1.004°`；通过，运动距离超过 3 m 且未摔倒 |
| 阶段 5：抗扰动测试 | 在平衡状态下施加持续 `0.1 s` 的 `2 Nm` 左右车轮差动力矩 | 俯仰角绝对值峰值为 `6.15°`，并在 `5.9 s` 时恢复至 `1.81°` |
| 键盘输入测试 | 通过 `keyboard_joy` 模拟按下 Up 键 | `/joy` 成功到达控制器；按住按键时目标速度增加，松开按键后目标速度恢复为零 |
| 手柄输入测试 | 在 `/joy` 上使用标准 Xbox 手柄轴布局 | 无设备，暂未测试 |

### 测试结果说明

本次测试表明，在所述仿真环境和参数配置下：

1. ROS 2 通信链路能够正常工作。
2. 车轮 PI 控制能够实现符合测试标准的速度跟踪。
3. VMC 腿长控制能够将腿长误差维持在规定范围内。
4. LQR 平衡控制能够在静止和运动状态下维持机器人稳定。
5. 在施加短时外部扰动后，机器人能够逐渐恢复平衡。
6. 键盘输入链路已经通过模拟按键进行了验证。
7. 手柄轴映射已在配置中定义。
